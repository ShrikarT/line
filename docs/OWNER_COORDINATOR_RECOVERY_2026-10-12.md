# Whole financial coordinator recovery — 12 October 2026

The experimental private-offer coordinator now reconstructs generated Compact execution in a new process for every command. Its financial openings are stored in the encrypted source/instance-bound journal; the parent fixture receives public state and bounded status, not books, salts, nullifier keys or witness packets. Role approvals come from the existing four mTLS services. This closes a demonstrated local request-loss gap, not the product's privacy, independent custody, network or settlement gates.

## Bug and change

Previously, a coordinator could generate a new request and call the owner before saving that request. If the owner committed the approval and the coordinator died, its replacement lost the original randomness. Retrying the same operation ID with a newly generated descriptor could be rejected by the owner's idempotency guard; creating a new ID would risk another authorization reservation.

`PrivateFinanceJournal.stageAuthorization` now durably saves the semantic request, exact projected descriptor, circuit arguments, predecessor and pre-approval witnesses **before** the owner RPC. Only the identical intent may resume. After approval, `prepare` checks the saved inputs and atomically replaces the intent with the private candidate. A pending candidate blocks new work. Confirmation retains the existing exact candidate check; an exact completed semantic retry returns its completion without requesting another approval. Changed completed requests reject.

The worker also computes `flatFee + ceil(amount * basisPoints / 10000)` with BigInt, validates UInt64 terms/cost and reports a staged operation ID so recovery status does not falsely appear idle. Compact remains the source of truth and checks the actual fee, capacity, merchant membership, approval and claim rules. No Compact APIs or commitments are replaced. Canonical source and managed bindings are unchanged.

## Trust boundary and open work

This is a same-host synthetic fixture. Its launcher creates and owns all four software-owner keys, the TLS test CA/client credentials and the financial password. The worker is trusted with private financial openings and is not a hardware enclave. Separate processes and an API do not establish independent administrative custody. The financial journal keeps its v1 envelope with an optional intent field; legacy callers without staging remain supported. No production checkpoint migration or independently reviewed rollback/backup protocol is performed.

The default worker performs generated execution. Its optional `prove` command reconstructs the saved private candidate, checks the exact twelve-circuit key manifest and native executables, proves inside the worker, verifies in a separate Rust process and persists the public proven transaction before replying. The caller receives public bytes/state and bounded proof metadata, never private transcripts or witness packets. A subsequent worker re-verifies and reloads those exact transaction bytes without another approval or another proof. Proof caches use dedicated sibling directories; they cannot be placed inside the financial store, which correctly rejects unrelated files/directories.

The new [source-bound native integration](private-signed-2026-10-11-evidence/owner-coordinator-native-proof.json) completes all ten restored calls across six names, with separate Rust verification of every transaction. Sixty worker invocations include ten abrupt exits: the eight authorization/candidate/confirmation faults plus two after proven-transaction publication. Both draws recover identical transaction bytes without another approval/proof; changed predecessor bytes reject, and two decodable corrupted draw proofs reject. Twenty-six helper fingerprints, all-twelve IR/key fingerprints and native-executable hashes bind this run. Local proving totals **397,279 ms**, with a 37,329.5 ms median and 90,138 ms maximum over ten calls. Those are finite proving measurements, excluding network finality, asset settlement and much coordinator/transport overhead; they do not establish production latency. Two terminal attempts reached synthetic deployment but no contract call before a cache-layout failure. [Failed attempt metadata](private-signed-2026-10-11-evidence/owner-coordinator-native-attempts.json) is retained. The complete sequenced local Windows suite now passes **510 tests / 60 suites**, with compile/zero drift, build/typecheck and key/credential scans passing. The implementation `affbb49` passes [push CI](https://github.com/ShrikarT/line/actions/runs/38240491636); its [PR CI](https://github.com/ShrikarT/line/actions/runs/38240499278) stopped at anonymous GitHub API rate limiting during compiler installation. This is retained as a failed infrastructure check, not a passing PR result. The follow-up workflow token is limited to installation, as in the [official Compact setup action](https://github.com/midnightntwrk/setup-compact-action/blob/main/action.yml); it does not broaden native/network/asset claims. Three configuration/layout tests pass, including network/source/executable/key-manifest denials and actual dedicated-store isolation. These are guard/recovery controls, not substitute proof verification.

The worker never submits a transaction. `confirm` accepts a caller-supplied public candidate and does **not** authenticate a network receipt, finality, contract address in an observed transaction, or asset payment. It cannot close the confirmed-network gate. Approval budgets and reserve counters do not establish deposited capital or merchant payouts. Native mode uses synthetic ledger/time and a 45-minute quote TTL to accommodate local proving; it does not test wall-clock network expiry, live fee balancing or institutional ownership. Hard process death during an active native subprocess is not covered by the after-publication crash test; owned subprocess cancellation/recovery remains an operational requirement.

An intent whose approval expires, is denied, or cannot execute remains unresolved and blocks further work. Owner retry policy checks current time before returning a saved approval. There is no certified intent-abandonment, reservation-release, multi-party cancellation or receipt-reconciliation protocol; silently generating a replacement would defeat the recovery guarantee. Only the supported first-generation purchase path is wired into this experimental worker. Refunds, repayment, status, reopening, concurrent-root reconciliation and owner-key recovery need their own durable protocols and controls.

Full-history privacy is still open: the canonical deployment publishes debt increments, while the experimental source has finite serialized-history differences, traffic/timing correlations and a trusted financial prover. Padding application frames does not establish complete transcript privacy. The worker has no canonical browser/backend integration, funded network execution, real settlement, independently operated owners or customer demand evidence.
