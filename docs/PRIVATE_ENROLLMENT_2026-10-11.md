# Private enrollment query experiment — 11 October 2026

The preceding merchant source publishes whether opening uses a previous book and follows different ledger queries for fresh enrollment versus reopening. For a recognizable participant, reopening reveals a closed, zero-debt predecessor. This separate twelve-circuit candidate removes the explicit predecessor flag and those branch-dependent queries. It is not the deployed contract, browser runtime or a completed historical-privacy construction.

Source: `contracts/experimental/line-private-enrollment.compact`, SHA-256 `27759dbf6fd283f210c0832117139c81d6e6ec4a408386081987a1a2322fdd8f`. It retains the merchant membership, committed amounts/reserve books, external role approvals and exact settlement accounting. Its constructor uses a distinct instance-domain tag. It adds a supported `MerkleTreeDigest` witness for the current common book root; the ABI/witness implementation is versioned separately. Canonical source and managed bindings are unchanged.

Both fresh and reopened requests check the same current book root. Typed book/path witnesses and commitments are prepared unconditionally. Reopening privately verifies path membership, contract domain, borrower identity, closed status, zero debt and the next generation. Fresh enrollment uses a typed dummy path whose membership is not claimed. The current-root check still applies to it. Signature verification stays outside private branches.

The existing `initialEnrollments` set now stores generation-specific issuance nullifiers derived with actual Compact persistent hashing from the contract domain, stable secret key, borrower identity and private generation. Its old field name is retained but it is no longer initial-only. Every issuer acceptance checks/inserts an issuance nullifier and a spend nullifier. Reopening consumes the real predecessor; fresh enrollment inserts a separately domain-tagged, request-bound marker. Duplicate first-generation issuance and repeated predecessor spending reject. Both phases remain bound to the exact fresh book, predecessor commitment, terms and action through agent consent and issuer approval. This does not erase earlier public histories.

Fresh generated execution passes **39 normal calls, thirteen isolated branches and 66 rejection controls** across all twelve names. New controls cover stale enrollment roots, altered predecessor selection, duplicate first-generation issuance after a valid consent, an open predecessor and an already-consumed reopening predecessor. Two valid continuous histories begin at the same reachable closed-book state: one enrolls a different previously unused signer; the other reopens the closed book. Consent and acceptance have matching exported inputs/outputs and query counts **70/70 and 99/99**. They differ in five and ten public leaves respectively. Every difference is recorded as observed type/length/path; hex encoding does not demonstrate a hiding commitment or equivalent distributions. Acceptance states differ because each follows its own consent. [Source-bound generated evidence](private-signed-2026-10-11-evidence/enrollment-feasibility.json).

[The key manifest](private-signed-2026-10-11-evidence/enrollment-key-generation.json) records one newly generated opening pair (k=17, 79171 rows) and eleven cached pairs whose freshly generated textual IR is byte-identical to the source-bound, native-verified merchant predecessor. Artifact hashes are verified before use. This is not twelve fresh key generations or inherited native verification of this new source. A source-pinned native run is active and requires 39 normal proofs, all thirteen isolated proofs and six corrupted-draw rejections before reporting completion.

Remaining acceptance: actual proofs for this source and branches; a construction-level argument for nullifier/commitment distributions; full enrollment/refund/closure histories, catalogs, participant side information, fee-payer/sender/time metadata and asset events; consistent client scheduling and durable concurrency/recovery. If an observer already knows there is only one possible borrower and no fresh enrollment is possible, a successful opening can still entail a reopening. Matching queries cannot hide a fact forced by that knowledge. This finite population comparison does not certify the singleton case, anonymity, independent custody or complete history privacy. Native signers remain same-host ephemeral fixture processes with a trusted financial coordinator. No candidate deployment, payment or customer validation is established.

Harness provenance records both actual execution bytes and LF Git-storage fingerprints. The existing Windows `encoding.ts` worktree has CRLF and is retained unchanged while native verification is pinned; that difference is explicit rather than relabeled. Compact source and generated executable fingerprints identify exact bytes. Checkout rules now keep the encoding module and MJS harnesses at LF for future checkouts.

Reproduce generated controls with `npm run enrollment:spike`; fresh compilation is default. `--compiled-dir` is cached diagnostic use. Native reproduction, after full artifacts and a fresh source-bound fixture are available:

`npm run proof:enrollment -- <full-managed-dir> --compiled-check <fresh-fixture-managed-dir> --recycle-prover --recycle-each-call`

The driver owns only its labeled loopback prover, checks source/artifact/harness fingerprints and verifies every accepted transition through a separate Rust process. It uses synthetic ledger/time with fees disabled; network and genuine settlement remain separate gates.
