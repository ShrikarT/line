# Durable software approval signer — 11 October 2026

The current signer also supports the owner-selected `line-private-offer/v1` profile. It derives the exact eight-field supplier quote digest locally, accepts only opaque binding/invoice/price/nonce values and authenticates the ABI in its encrypted storage namespace. A request cannot select another ABI, and an offer journal cannot silently reopen under the legacy profile. Existing enrollment storage remains compatible under the default profile. Three added tests check the exact signature, restart/cached response, cross-profile rejection and private payload rejection; twenty signer tests and four child-actor tests pass.

All twelve action tuples now have explicit argument counts/types. Permitted value fields and nested books are type-checked before local policy. This closes a path where an unrelated book could be attached as an extra argument or substituted for a typed invoice/amount. It does not prevent an authorized malicious financial reader from intentionally leaking information outside the protocol.

`scripts/durable-approval-signer.mjs` is an experimental encrypted software signer for the existing signed private-finance approval scheme. It keeps its scalar behind a private class interface, derives the exact Compact action digest locally and returns public identity and approval fields. SHA-256 fingerprints the application journal only; persistent Compact hashing and commitments are unchanged. This is not a remote service, HSM or independent institution. A separate [durable agent integration](DURABLE_ACTOR_2026-10-11.md) now exercises six compiled and native-verified candidate calls; it is not the production runtime.

The owner supplies a storage key, custody identifier, role and local authorization callback. Binding pins the contract domain, policy configuration and callback source string; bindings cannot be raised or changed. Baseline role/mode gates are enforced independently of the callback. Action-specific field allowlists reject unknown top-level values, nested book properties and irrelevant openings before policy execution; merchants cannot receive a borrower book through a claim approval request. The prototype requires adapters to send only the permitted terms; the original native fixture is not wired to it. An agent draw must reserve its full private principal plus fee against a conservative persisted authorization budget. No automatic budget release or revolving-credit reconciliation is implemented. Local callbacks still need complete actor-owned business policies and supported migration.

Every returned approval follows an encrypted journal commit: temporary file write, file fsync and rename. Reusing an operation ID with altered terms fails; retrying unchanged terms rechecks policy and returns the originally committed response. A failed persistence operation returns no approval and requires reopening. An exclusive lease prevents overlapping owners. Stale lease recovery requires the exact recorded PID and a confirmed stopped process; it neither terminates processes nor infers death from a timeout.

Seventeen targeted tests pass, including public-key continuity, exact runtime Schnorr equations, changed-term rejection, wrong domain/merchant/borrower/expiry, role/budget bypass attempts, ciphertext authentication, wrong key/role/custody ID, overlapping leases, write failure and a real child-process exit after journal commit but before reply. That crash is recovered with the identical stored approval and no second budget reservation. Run `npm run custody:journal:test`; these tests also run in `npm test`. They are not generated-Compact or native-contract integration tests.

Remaining limits: no authenticated transport or independent administrative control; no demonstrated hardware-contained signing or independent cryptographic review; no external monotonic anchor against restoring an old valid ciphertext; no directory fsync/power-loss guarantee or verified Windows ACL setup; ancestor directories/storage and local callback dependencies remain trusted. The callback source fingerprint does not pin external helpers or closures. A crash during stale-lease recovery can leave its recovery guard requiring operator handling. Operation storage is bounded at 256 records and fails closed at capacity; retention/compaction is not implemented. Closing wipes the local storage-key buffer, but does not establish scalar-memory zeroization.

The native merchant report still uses its original same-host ephemeral fixture signers. The separate durable-agent experiment verifies approvals in freshly compiled Compact and six real native-verified calls through two restarts. Next acceptance work must extend this to independently administered issuer, agent and merchant actors and minimize per-role request data. Persisted financial openings, chain confirmation, uncertain submission recovery, key loss/migration and genuine settlement remain separate requirements. Existing funded wallet seeds are unnecessary for this synthetic prototype.
