# Durable software approval signer — 11 October 2026

`scripts/durable-approval-signer.mjs` is an experimental encrypted software signer for the existing signed private-finance approval scheme. It keeps its scalar behind a private class interface, derives the exact Compact action digest locally and returns public identity and approval fields. SHA-256 fingerprints the application journal only; persistent Compact hashing and commitments are unchanged. This is not a remote service, HSM, independent institution or integrated runtime.

The owner supplies a storage key, custody identifier, role and local authorization callback. Binding pins the contract domain, policy configuration and callback source string; bindings cannot be raised or changed. Baseline role/mode gates are enforced independently of the callback. An agent draw must reserve its full private principal plus fee against a conservative persisted authorization budget. No automatic budget release or revolving-credit reconciliation is implemented. Local callbacks still need complete actor-owned business policies and supported migration.

Every returned approval follows an encrypted journal commit: temporary file write, file fsync and rename. Reusing an operation ID with altered terms fails; retrying unchanged terms rechecks policy and returns the originally committed response. A failed persistence operation returns no approval and requires reopening. An exclusive lease prevents overlapping owners. Stale lease recovery requires the exact recorded PID and a confirmed stopped process; it neither terminates processes nor infers death from a timeout.

Fifteen targeted tests pass, including public-key continuity, exact runtime Schnorr equations, changed-term rejection, wrong domain/merchant/borrower/expiry, role/budget bypass attempts, ciphertext authentication, wrong key/role/custody ID, overlapping leases, write failure and a real child-process exit after journal commit but before reply. That crash is recovered with the identical stored approval and no second budget reservation. Run `npm run custody:journal:test`; these tests also run in `npm test`. They are not generated-Compact or native-contract integration tests.

Remaining limits: no authenticated transport or independent administrative control; no demonstrated hardware-contained signing or independent cryptographic review; no external monotonic anchor against restoring an old valid ciphertext; no directory fsync/power-loss guarantee or verified Windows ACL setup; ancestor directories/storage and local callback dependencies remain trusted. The callback source fingerprint does not pin external helpers or closures. A crash during stale-lease recovery can leave its recovery guard requiring operator handling. Operation storage is bounded at 256 records and fails closed at capacity; retention/compaction is not implemented. Closing wipes the local storage-key buffer, but does not establish scalar-memory zeroization.

The native merchant report still uses its original same-host ephemeral fixture signers. Next acceptance work must integrate owner-controlled actors, minimize per-role request data, verify the exact approvals in freshly compiled Compact and repeat the lifecycle with native proofs. Persisted financial openings, chain confirmation, uncertain submission recovery, key loss/migration and genuine settlement remain separate requirements. Existing funded wallet seeds are unnecessary for this synthetic prototype.
