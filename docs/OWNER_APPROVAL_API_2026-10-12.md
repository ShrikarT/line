## Authentication and disclosure

The owner requires TLS 1.3, a trusted client certificate and an exact approved client-certificate fingerprint. The caller validates CA/hostname and the pinned owner leaf certificate **before sending its body**, then checks the owner's role, private-offer ABI, domain and Compact public point. A public point echoed by an endpoint alone is not authentication; TLS possession and the certificate pin establish the transport peer. Each approval must also match the expected public point, and Compact still verifies its actual signature and accounting constraints.

Application bodies have fixed sizes: 128 KiB requests and 8 KiB responses, including private JSON encoding and randomized padding. Typed witness data travels inside TLS. Accepted and policy-denied approvals return equally sized application bodies; denial copy is `Approval could not be authorized.` These lengths do not make HTTP headers, TLS records, peers, caller attribution, frequency, routing or timing indistinguishable. No full-history privacy claim follows from padding. The product's rejected-draw boundary still requires `Clearance could not be proven.`; this experimental owner API is not wired into the product UI.

Malformed/oversized frames, unknown request fields, foreign domains, incorrect roles, unexpected private values and unapproved certificates reject. The existing signer enforces typed per-circuit tuples, role restrictions, immutable owner policy/domain/ABI, operation-ID equality and cumulative authorization bounds, and commits before responding. The API has sixteen-connection and five-second request/header bounds. These are prototype resource limits, not a denial-of-service assessment.

An uncertain transport response never causes an automatic new operation or new operation ID. Preserve the exact request and reconcile/retry that identity. Existing signer retries remain subject to its current owner policy and clock; retrieval after deadlines, complete coordinator reconstruction, certificate/key rotation, rollback resistance and device-loss recovery need separate procedures. An authorization counter is not a ledger balance or payment receipt.

## Owner setup

`npm run owner:service -- <owner-profile-file>` starts the CLI. The profile uses the repository's `encodeVaultJson` format, so bytes and BigInts retain their types. It contains:

- `version: 1`, `approvalABI: "line-private-offer/v1"`, role and custody namespace;
- owner-only store directory and explicit `createIdentity` choice;
- local policy module path, its exact SHA-256 source fingerprint, and immutable typed policy configuration;
- listen host/port, owner TLS key/certificate/CA paths and allowed client-certificate fingerprints.

The owner supplies `LINE_APPROVAL_OWNER_STORE_KEY_HEX` in its own process environment: a separate 32-byte software-store key, not a wallet seed. The CLI removes its environment reference after reading it; this is not heap zeroization or hardware containment. The coordinator needs its own TLS client credential and public owner pins, but never this store key or the owner's TLS private key. Real operators must protect their local profile, source/dependencies, TLS files, environment and encrypted store under their own access controls. The top-level policy-module fingerprint is not a transitive dependency attestation.

For bootstrap, the owner can use `--identity` to create/read its encrypted identity and print its public point without serving or binding a policy. Creation is explicit: after creation, subsequent runs use `createIdentity: false`. Owners then verify the selected contract domain, counterpart public identities and terms out of band before binding their policies. The API cannot perform this setup for them. Do not copy the test harness's shared CA, synthetic owner keys or same-account administration into a deployment claim.

The supplied `approval-owner-example-policy.mjs` demonstrates bounded first-generation purchases. Issuer policy allows selected merchant registration/disable, bounded reserve authorization and consent acceptance for a specific borrower/terms; agent policy checks its own book, merchants, price/fee and time; merchant policy checks its opaque facility binding, price and time bounds. Other governance, receipt, refund and dispute operations deny by default. Those require an owner-selected policy with real reconciled terms/receipts; enabling them blindly would not establish cash authenticity. The underlying Compact source still exports exactly the same twelve circuit names.

Clean shutdown uses the owner's local `stop` input or process signal; there is no network stop route. A hard-death signer lease still requires the existing owner-only stopped-PID recovery procedure. OS administration, process-death uncertainty, production backup and institutional key custody are not certified here.

## Reproduction and remaining integration

`npm run owner:service:test` runs the transport/CLI controls. `npm run owner:service:compact` freshly compiles the exact private-offer source and executes the two-merchant integration. Certificate fixtures use OpenSSL; Windows tests use the existing Ubuntu WSL OpenSSL and create files only in ignored test directories. No operator wallet, existing TLS key, funded helper or global Docker/WSL configuration is used.

Canonical Compact and managed bindings are unchanged. Earlier 65-call and six-call native reports retain their exact historical helper fingerprints; the new owner API has its separate ten-call native report above. Closing the destination still requires whole-coordinator/durable all-role recovery, independent owner deployments and policies, runtime/console integration, complete observer histories, fee-funded finalized network calls, authentic asset settlement and customer evidence. The Wave 2 privacy-demo gate remains open.

Transport APIs follow the [Node HTTPS server](https://nodejs.org/api/https.html#httpscreateserveroptions-requestlistener) and [TLS peer-certificate](https://nodejs.org/api/tls.html#tlssocketgetpeercertificatedetailed) interfaces. These primary API sources establish library behavior, not Line's privacy or custody assurance.
