# Remaining compensation integration requirements

Continuation: [all-twelve generated compensation/recovery](COORDINATOR_COMPENSATION_2026-10-13.md) now implements all three modes, note-bound encrypted owner receipt admission, saved refund openings and a strictly preview-only clock. Its 30-call/92-exit/82-control result is generated-only. Native/network/real-receipt/privacy/independent-custody requirements below remain open; the original planning baseline is preserved.

`cancelOrExpireNote` remains the last undispatched private-worker name after the repayment/reopening implementation. This is a source-based implementation plan, not completed execution evidence. Preserve the twelve existing circuit names and the exact Compact hashes, quantities and authority rules.

| Mode | Required authority and state | Private custody to retain | Accounting consequence |
|---|---|---|---|
| 0 — expire | Authenticated signer; original note unredeemed, not already cancelled and actual ledger time at/past its expiry | Archived note metadata opening/salt and reserve opening/salt; typed unused witnesses still required by the compiled function | Principal and pending fee move into a full-cost refund hold; debt is unchanged |
| 1 — allocate | Issuer or original borrower; unredeemed note, not already allocated, expired or cancelled; authentic current same-owner book and original note opening | Original note identity/generation/quote/nonce/salt; current book/path/salt; saved new salt and exact allocated refund amount/opening | Current-generation cost credits debt down to zero; excess becomes cash owed. Earlier-generation claims preserve current debt and owe full cost. A zero-cash allocation releases its hold; positive cash retains the full original budget |
| 2 — acknowledge refund | Issuer; cancelled/allocated note, not already acknowledged; authentic saved refund opening; valid receipt deadline, nonzero unused reference and exact allowed amount | Original note identity/generation; allocated refund amount and salt; exact owner-authenticated refund receipt/reference | Positive refund moves the full original budget from refund hold to reported hold; zero obligation moves no holds. Acknowledgment does not establish actual payout or free the reported hold |

The source computes these quantities and commitments before action selection. Supplying only the obvious active-mode witnesses is insufficient. In mode 2 the refund-opening salt is the saved allocation salt; substituting the current book salt after another transition must reject.

Mode 1 must persist its new book and refund opening in the prepared candidate before any response. Later draws, repayments, reopening or newer same-supplier notes cannot replace that refund record. Key refund custody by the original `D`; latest supplier selectors remain conveniences. Mode 0/2 must not accidentally rotate the current book. Every completed retry retains its original mode, reference, amount, deadline, nonce and salts.

Receipt admission must distinguish a repayment from a refund and bind the actual denomination, liable party and recipient/facility. A synthetic allowlist is permissible only as explicitly labeled test configuration. The same source-defined payment nullifier applies across repayment and refund modes; a previously used reference cannot be reintroduced by changing an epoch, generation or receipt nonce. Match the experimental `line:v2:payment` encoding exactly, independently of canonical v3 helpers.

Expiry testing needs a separate preview-only time facility, persisted under the synthetic journal realm and prohibited while authorization, submission or a candidate is unresolved. It must not be selectable as Preprod time. Network execution must obtain time/finality from authoritative ledger observations. Native transaction verification must use the same saved execution time and require a continuous public state chain; updating fixture metadata is not a finalized block.

Required generated scenarios include debt-only, partial cash, full cash after reopening, zero-obligation acknowledgment, both allocation roles and both merchants; receipt/refund salt survival after later transitions; all four write-ahead interruption boundaries; mode substitution/reuse, wrong owner/supplier, premature expiry, redemption after cancellation, repeated allocation/acknowledgment and cross-mode payment-reference reuse. Verify lock conservation against authenticated Compact openings. Only after those pass should the new exact source/key/helper path be natively proved and then reconciled against finalized network receipts and real assets.

Completing these modes will not by itself close full-history privacy, independent institutional custody, receipt authenticity, real settlement, multi-borrower/fleet concurrency or the hackathon entry package.
