# Proof-worker process ownership — 12 October 2026

The experimental native coordinator now requires a fingerprinted process guardian before dispatching any command. Worker readiness alone cannot start proving. A worker result is returned only after its process exits and guardian termination completes. Setup failure, unexpected guardian loss and uncertain cleanup reject the operation; they do not permit a replacement financial request or a claimed confirmation.

## Operating-system boundary

On Windows, the guardian creates an unnamed Job Object, sets `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` and assigns the already-created financial worker before announcing readiness. Descendants inherit that job; breakaway flags are not enabled. Its unique, noninherited job handle is held by the guardian. Worker exit or owner-channel loss terminates the job and checks that its active process count reaches zero. Hard guardian death closes its handle in the kernel and terminates members. This avoids relying on JavaScript finally blocks or guessing descendant PIDs. [Microsoft's Job Object behavior](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects).

On POSIX, Node starts the worker in a dedicated process group. The guardian checks that isolation before readiness and kills that group when the worker/owner channel is lost. The worker also kills its group on unexpected IPC disconnect, while deliberate completion exits normally. This is a cooperative trusted-process boundary, not Windows-style kernel containment: descendants must not leave the group, and simultaneous guardian/worker hard kills are not a universal guarantee. CI tests the supported group behavior on Linux; it does not certify stronger containment.

The guardian accepts only a numeric worker PID and a lifetime pipe. It reads no keys, private journals, preimages, wallet state or network receipts. The controller uses the PID of its own newly spawned worker and verifies the guardian executable hash. The supervisor is trusted local code, not a new remote authorization interface, hardware custody or enclave attestation. Independent ownership of issuer/agent/merchant keys remains a separate gate.
