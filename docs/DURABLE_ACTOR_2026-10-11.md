# Durable agent and Compact interoperability — 11 October 2026

The encrypted software signer now participates in a real compiled-contract and native-proof lifecycle. This is a synthetic same-host experiment; the test owner supplies the encryption key to the launcher. It does not establish independent administrative custody.

The exact enrollment source is `contracts/experimental/line-private-enrollment.compact`, SHA-256 `27759dbf6fd283f210c0832117139c81d6e6ec4a408386081987a1a2322fdd8f`. No signing scalar is passed as a contract witness. The agent runs in a child process with an immutable domain and owner-configured policy. Approver IPC offers approval and shutdown only. Policy checks bind borrower identity, merchants, price, fees, accepted facility terms, expiry and a conservative persisted authorization budget.

Fresh generated execution performs six calls: reserve funding, agent opening consent, issuer opening acceptance, merchant quote, agent draw and merchant redemption. The agent is stopped and restarted after consent and after draw. Both restarts preserve its public identity and return exactly the committed approval. Four requests reject at the actor policy boundary. Reusing the recovered draw approval after the state advances rejects in Compact without a second debit. [Generated evidence](private-signed-2026-10-11-evidence/durable-agent-compact.json).

All six accepted contract calls also pass real proof generation and a separate Rust cryptographic verifier. A decodable corrupted draw proof rejects. The report contains seven transactions including the synthetic deployment, covering five distinct circuit names. It is **not all-twelve coverage**; the separate [enrollment report](PRIVATE_ENROLLMENT_2026-10-11.md) provides that coverage. [Native evidence](private-signed-2026-10-11-evidence/durable-agent-native-proof.json). Source, harness, executable and key hashes are checked before completion. The owned loopback prover is stopped afterward.

Three additional child-process tests cover restart identity/approval continuity, persistent budget, malformed or foreign requests and opening terms. Together with seventeen journal tests, these are twenty targeted software-custody tests. They do not establish power-loss safety, anti-rollback, authenticated remote transport, hardware signing or a reviewed signature scheme.

The financial coordinator still holds authorized private openings in volatile memory. Issuer and merchant signers remain ephemeral fixture processes. The launcher knows the synthetic encryption key, and all actors share one administrative host. The test does not demonstrate recovery of the complete financial state, independent institutional ownership, network finality, asset payment or customer acceptance.

Historical privacy also remains unresolved: the current merchant quote request contains borrower identity, generation and fee policy. A merchant who knows a zero starting balance, a 15-unit purchase and its 1-unit fee can infer 16 units owed. Moving these fields out of public ledger state does not protect them from that merchant. The next design must minimize supplier request data and bind quotes to a private facility without exposing its fee policy or numeric generation, while retaining exact accounting and replay protection.

Reproduce actor tests with `npm run custody:actor:test`, fresh generated integration with `npm run custody:compact`, and native integration with `npm run proof:custody -- <full-managed-dir> --compiled-check <fresh-generated-managed-dir> --recycle-prover --recycle-each-call`. The proof run uses synthetic time and ledger state with fee balancing disabled. Fresh compilation is the default for generated integration; cached bindings are diagnostic inputs and explicitly labeled.
