# Private financial checkpoint recovery — 11 October 2026

The combined durable-agent/private-offer experiment previously preserved the agent's signing identity but left reserve, book, quote and note openings in coordinator memory. This revision persists a source- and instance-bound financial checkpoint before proving and retains an unresolved candidate until the authorized coordinator observes its accepted state.

`scripts/private-finance-journal.mjs` uses the existing encrypted checkout store's AES-GCM, exclusive process lease, bounded files, flushed temporary publication, atomic rename and OS access controls. The store now exposes an explicit `openBound` entry point; ordinary checkout still obtains its own authoritative source binding. Financial provenance includes a distinct protocol schema, network identifier, exact Compact source/executable fingerprints, contract address and contract domain. SHA-256 fingerprints storage provenance and bytes; Compact commitments still use the real Compact APIs.

The checkpoint contains public state bytes, private reserve/quote/note state, current book openings and salts, per-offer binding salts and the stable nullifier key. A prepared operation also preserves its original witnesses, circuit arguments and candidate checkpoint. It blocks a competing operation, rejects operation-ID substitution, and keeps the old confirmed checkpoint when the candidate is not observed. Publication failure closes the writer until reopening; confirmation updates checkpoint and completed-operation record together. The journal holds up to 256 operation identities, with explicit archival required thereafter.

Six tests pass, covering cross-process prepared/confirmed restoration; wrong password, source, executable, contract, domain or network rejection; exclusive writers and unresolved candidates; ciphertext tampering and absence of plaintext openings; process exit after publication but before response; and an actual failed filesystem publication followed by committed-state recovery. The process-loss test leaves a lease and recovers it only after its PID is confirmed dead. These tests establish local behavior, not network finality or resistance to restoring an entire older authentic disk image. The complete sequenced regression passes **493 tests / 60 suites**; canonical compilation/zero drift, typecheck and fixture/credential scans pass.

Fresh compiled execution passes the same six lifecycle calls and two agent restarts using **20 separate storage subprocess invocations**. Before each proof, it persists the candidate, clears the coordinator's financial memory and restores from a new storage process. It re-executes the saved witnesses through actual generated Compact and requires exact candidate/public/private state equality. Restored book openings must exist in the actual Compact book tree. The final checkpoint retains debt 16, book salt, private metadata and all six completed IDs; replay still cannot debit twice. Subsequent generated diagnostics preserve exact proof data, query effects, block context and commitment openings on reload. The storage subprocesses restart; the whole proof coordinator is not killed or reconstructed. Owner configuration and synthetic encryption password remain known to the launcher. Source-bound normalized public checkpoint bytes omit verifier-key registration metadata; the native driver must check actual ledger value-tree equality and verify the proof before confirming them. The journal's confirmation API trusts its authorized caller and does not fetch or authenticate network receipts. Windows power-loss durability, anti-rollback, independent administration, production key recovery, all-twelve financial recovery, funded network uncertainty, authentic settlement and full-history privacy remain unverified.

The new generic store entry point changes the checkout implementation fingerprint. Existing local checkout snapshots therefore fail their original source binding; no automatic migration is supplied. The owner workspace and deployed canonical contract are unchanged. An operator needs an explicit recovery/migration procedure before adopting a different bound implementation.

The first remote CI runs for `4db36c2` passed 492/493 tests. The fault-injection test restored a checkpoint with default public permissions on Linux, and the store rejected it. Its restoration now explicitly uses mode `0600`; the storage check is unchanged. Six targeted journal tests pass locally after the correction, with fresh Linux CI still required.

Reproduce with `npm run finance:journal:test` and `npm run finance:compact`. Native verification requires full private-offer keys and fresh source-bound recovery evidence: `npm run proof:finance -- <full-managed-dir> --compiled-check <fresh-generated-managed-dir> --recycle-prover --recycle-each-call`. It requires six native-accepted calls, five circuit names, one corrupted draw rejection, restored financial memory and all 20 storage invocations.
